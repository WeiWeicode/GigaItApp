# 架構觀測 使用手冊

> 對象:IT 人員(看監控、查問題)。位置:GigaItApp「**API Gateway 管理 › 架構觀測**」與「**總覽 › 儀表板**」。
> 資料來源:giga-observe 觀測服務(測試區、正式區各一套,畫面只看得到所在部署區的資料)。規劃見 Gateway `docs/MONITORING-PLAN.md`;維運見 `giga-observe/docs/OPERATIONS.md`。

---

## 1. 權限

| 畫面 | 權限代碼 | 說明 |
| --- | --- | --- |
| 架構觀測(選單) | `it.gw-observe.read` | 隨附 API 權限 `observe.data.read` |
| 架構圖 / 紀錄 / 錯誤 / 流量與來源 IP(Tab) | `it.gw-observe.map` / `.logs` / `.errors` / `.traffic` | |
| 查看請求 / 回應內容(按鈕) | `it.gw-observe.body` | 隨附 `observe.log.body`;內容可能含個資,只給需要查問題的人 |
| 儀表板「營運總覽」「Gateway 概況」的監控數字 | `it.dashboard.overview` / `.gateway` | 隨附 `observe.data.read`;沒有時顯示「開發中」 |

角色 `it-admin` 預設全部都有;其他人在「系統管理 › 權限設定」授予(角色 / 部門 / 個人皆可)。

## 2. 架構圖

- **分層**:展示層(前端)→ 接入 / API 層(Nginx、BFF、各系統後端)→ 核心服務 → 資料與儲存 → 維運與基礎設施。連線表示呼叫關係,線上的文字是用途(例 `/api/it/*`)。
- **節點**:左側色條與圓點是狀態;下方是**近 1 小時**的請求數、錯誤數與平均耗時(Nginx 為流量彙總)。虛線外框 = 規劃中的服務。
- **上方狀態計數**:點「正常 / 異常 / 失聯 / 未回報」可只亮出該狀態的服務;搜尋框可找名稱、代號、技術棧。
- **滑鼠移到節點**:亮出與它相連的服務;**點節點**開服務詳情。
- 每 15 秒自動更新(右上角顯示最後更新時間);分頁切到背景時暫停。

### 2.1 狀態怎麼判斷

| 狀態 | 條件 |
| --- | --- |
| 正常 | 90 秒內有心跳或探測成功,且近 5 分鐘錯誤率 < 5% |
| 異常 | 活著,但近 5 分鐘錯誤率 ≥ 5%(5xx 或服務自報錯誤) |
| 失聯 | 超過 90 秒沒有心跳、探測也失敗 |
| 未回報 | 從未收到心跳或探測(尚未接入、或拓樸登錄了但服務還沒上線) |

前端(例 `itapp-web`)的錯誤率 = 前端錯誤 ÷ 頁面瀏覽數。

### 2.2 服務詳情

| 分頁 | 內容 |
| --- | --- |
| 概況 | 服務代碼、類型、說明、技術棧、Repo、**版本**(部署的 commit)、運作時間、最後心跳 / 探測、近 1 小時統計、**相依服務**狀態(例 BFF 的 sqlserver、redis) |
| 紀錄 | 近 24 小時最新 50 筆;點一列看明細 |
| 錯誤 | 近 24 小時最新 20 筆錯誤 |
| 相依 | 上游(呼叫本服務的)與下游(本服務呼叫的),點代號可切換到該服務 |

## 3. 紀錄

- 篩選:服務、時間(1 小時 / 24 小時 / 7 天)、等級(錯誤 / 警告)、狀態碼(`500` 或 `5xx`)、路徑關鍵字、**Request ID**。
- 一次 50 筆,往下按「載入更多」。
- 路徑下方的「→ itapp-api」表示 BFF 把這個請求轉給哪個上游。

### 3.1 用 Request ID 追一個請求

同一個請求在 Nginx、BFF、後端、前端都帶同一個 Request ID(`X-Request-Id`):

1. 使用者回報錯誤時,畫面的錯誤訊息會附 `requestId`(GigaItApp 的 toast 也會顯示)。
2. 在「紀錄」的 Request ID 欄貼上,時間範圍自動放寬到 7 天。
3. 會列出 BFF 的那一筆(含轉給哪個上游、耗時)和後端的那一筆(含步驟、錯誤堆疊),前端錯誤也會出現。

明細視窗裡按「查同一請求的所有紀錄」效果相同。

### 3.2 紀錄明細

- 路徑樣板、使用者工號、Gateway 路由代碼、Request ID、錯誤訊息。
- 有「查看請求 / 回應內容」權限才看得到:**步驟**(資料庫、外部 API 各花多少時間)、**錯誤堆疊**、請求 headers / query / body、回應 body。
- 密碼、Token、API Key、Cookie 等欄位已遮罩為 `***`。成功的請求只留前 1 KB;錯誤保留完整內容 **90 天**,之後只留前 1 KB 摘要。

## 4. 錯誤

- 同一服務 + 方法 + 路徑樣板 + 狀態碼合併成一組,顯示次數、首次 / 最後發生與範例訊息。
- 篩選:服務、時間(24 小時 / 7 天 / 30 天)、`5xx 與自報錯誤` / `4xx` / 全部;排序依次數或最近發生。
- 點一組 → 個別事件 → 點事件看明細。
- 保存:5xx 與自報錯誤**永久**;4xx 只留 7 天(多為參數或權限問題)。

## 5. 流量與來源 IP

| 區塊 | 內容 |
| --- | --- |
| KPI | 期間內 Nginx 請求數、5xx、401 / 403、429 限流、傳輸量 |
| Nginx 流量 | 1 小時看每分鐘,24 小時 / 7 天看每小時;請求數、4xx、5xx |
| 資安告警 | 近 15 分鐘:拒絕請求(401 / 403 / 429)突增、單一 IP 請求異常、登入失敗突增 |
| 來源 IP 排行 | 請求數、5xx、被拒次數、最後出現;由每分鐘前 20 名合併,為近似值 |
| 前端效能 | 各前端近 24 小時的 p75(抽樣 10% 的使用者):LCP 最大內容繪製、INP 互動延遲、CLS 版面位移、FCP、TTFB、載入完成;評等「良好 / 待改善 / 差」依 web.dev 門檻 |

> 告警只在畫面顯示,目前不寄信。告警標示「未經 PROXY protocol」時,來源 IP 是 Docker 網段而不是使用者電腦,需檢查主機的 L4 轉送設定。

## 6. 儀表板

| 卡片 | 計算方式 |
| --- | --- |
| 今日 API 呼叫 | 今天(台灣時間 0 點起)經 BFF 的請求數;與昨日同時段比較(昨日少於 50 次時不比較) |
| 服務可用率 | 非 5xx 的比例 |
| 平均回應時間 | BFF 處理時間平均;下方顯示 p95 |
| 資安告警 | 近 15 分鐘資安告警件數;下方顯示系統告警件數 |
| 今日 API 流量 | 每小時請求數與錯誤數 |
| 系統告警 | 服務失聯、錯誤率偏高、前端錯誤突增;點「架構觀測」到架構圖 |
| Gateway 概況 › 上游服務健康 | 近 1 小時 BFF 轉送到各上游的 p95 與可用率(錯誤率 ≥ 5% 或 p95 > 1 秒顯示「偏慢」) |
| 待處理工單 | 開發中 |

沒有監控權限,或觀測服務尚未接入時,這些卡片顯示「開發中」,不影響其他區塊。

## 7. 常見問題

| 狀況 | 原因 / 處理 |
| --- | --- |
| 選單沒有「架構觀測」 | 沒有 `it.gw-observe.read`;請管理員在權限設定授予 |
| 畫面顯示「觀測服務尚未接入」 | Gateway 沒有 `/api/observe/*` 路由(新部署區尚未匯入),見維運手冊 §3 |
| 某服務一直「未回報」 | 服務沒有接 SDK、沒有 Key,或拓樸登錄的探測網址錯誤;見維運手冊 §4 |
| 架構圖出現「有服務在回報但未登錄」 | 服務用了 Key 在回報,但拓樸沒有這個服務代碼;維運手冊 §4.2 |
| 明細看不到請求內容 | 沒有「查看請求 / 回應內容」權限,或該筆超過 90 天只剩摘要 |
| 前端節點「0 次」 | 前端只回報頁面瀏覽與錯誤;只在正式建置的版本回報,本機開發不回報 |
